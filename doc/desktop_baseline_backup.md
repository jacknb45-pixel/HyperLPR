# 桌面（代理平台）基线数据备份

> **状态**：2026-11-01 起从 `doc/confirmation_report.typ` 开题报告中整体移除（按队长要求，开题报告只保留 Android 真机口径；开题阶段仅提交报告 PDF，仓库不交给老师）。
> 本文件为**组内备份**，不参与报告编译。中期做端云对照时，本数据即"云侧成本"的天然基线——云端 FastAPI 微服务大概率同样跑在 x86 + ONNXRuntime 上，届时它重新变为承重数据。

## 环境

- WSL Ubuntu（共享 32 核 x86_64 CPU）/ Python 3.12 / ONNXRuntime（CPU 执行）/ OpenCV
- 模型：`hyperlpr3` 自带 4 个 ONNX 权重（检测 y5fu_320x/640x、识别 rpv3_mdict_160、分类 litemodel_cls_96x）
- 输入：`test_img.jpg`（1920×1080）

## 四阶段分解（20 轮均值）

| 阶段 | 均值 (ms) | 标准差 | 占比 | 是否 AI 推理 |
|---|---|---|---|---|
| Stage 1 目标定位 | 18.54 | ±5.65 | 20.1% | 是 |
| Stage 2 几何对齐 | 0.67 | ±0.14 | 0.7% | 否（几何） |
| Stage 3 字符识别 | 71.09 | ±25.99 | 77.2% | 是 |
| Stage 4 属性分类 | 1.74 | ±2.19 | 1.9% | 是（条件触发） |
| **合计** | **92.04** | — | 100% | — |

资源占用：峰值 RSS **142.6 MB**；CPU **31.0 等效核心**（1.0 = 跑满一核，折合 32 核整机约 97%，即 ONNXRuntime 默认 intra_op = 全核几乎吃满整机）。

## 双平台对照（原报告 §6.5 摘录）

- 同一张 1080p 图：真机（8 核 ARM + MNN，算子口径）141.49 ms vs 桌面 92.04 ms → **1.54×**；核数少 4 倍而耗时仅多 54%，多核并行的边际收益有限。
- 逐项：Detect 桌面 18.54 → 真机 68.00 ms（**慢 3.67×**）；Rec 两端几乎相同（71.09 vs 70.08 ms，差 1.4%）；Cls 1.74 vs 2.53 ms。
- **阶段占比不跨平台守恒**：桌面 Rec 77.2% / Detect 20.1%，真机 Rec 49.5% / Detect 48.1%。根因是算子可并行度不同——Detect 卷积密集、吃多核红利；Rec 为 CRNN 循环结构、不吃多核（真机线程 1→8 时延跨度仅 3.7% 佐证并行度已近饱和）。
- 推论：若按桌面数据估计"卸载 Rec 可省 77% 算力"，在真机上会被显著高估（实际 49.5%）。**依赖阶段占比的定量结论必须在目标平台上重测**；切分点位置、载荷削减比例等结构性结论可跨平台迁移。

## 复现性与波动

- 同环境连续三次独立运行（每次 20 轮）端侧合计 **89.93 / 94.55 / 104.86 ms（±8%）**，波动来自 WSL 共享 CPU 调度噪声；RSS 142.7–144.3 MB、切片字节数等资源项高度稳定 → 噪声属环境而非测量方法问题。
- 真机侧逐阶段标准差 <2%，远稳于桌面；中期如需精细标准差对照，以真机口径为准。
- 终期前建议在物理机（非 WSL）复测一组对照，消除虚拟化噪声（已列入计划表"多机型真机复测"项）。
